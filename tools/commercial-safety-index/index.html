Methodology

Each record states HOW it was verified. sandbox-eval: tool smoke-tested and license read from its repository source in our sandbox (2026-07/08 runs). source-verified: LICENSE/NOTICE file fetched from the tool's own GitHub repository on 2026-08-22 and matched against SPDX license patterns; content hash recorded in the verification log. source-unmatched: a LICENSE file was fetched but did not match any pattern we trust. heuristic: no primary source was reachable from the record; the assessment is an LLM judgment from secondary sources and is labeled as such. This is a developer-efficiency reference, not legal advice. Records sourced from our broader tool catalog without a reachable primary license source are included at tier 'heuristic' and are never upgraded without a primary-source check.

Limitations, stated plainly: this index covers our catalog records (289); it is not a census of open-source AI tooling. Licenses can change after each row's verification date. Reuse is CC-BY-4.0 with attribution to Local-First AI Dev Notes.

Get alerted when a license flips

We do not collect emails. To be alerted when a grade changes, watch the public dataset repository (every re-verification run is committed there), or follow the Local-First AI Dev Notes store for packaged releases.

Frequently asked questions

What does commercial-safe mean here?

A tool is marked commercial-ok when its primary license is permissive (MIT, Apache-2.0, BSD, ISC, MPL-2.0, CC-BY, CC0 and similar), which permits use inside commercial products when license notices are kept. Tools with strong copyleft, network-copyleft or share-alike licenses are marked conditions apply, because shipping them can trigger obligations such as source disclosure.

How were the licenses verified?

Three ways, stated per row. Smoke-tested: we ran the tool in our own sandbox and read the license from its repository source. Source-verified: we fetched the LICENSE file from the tool's GitHub repository on the date shown and matched it against SPDX patterns, keeping a hash of the file in our verification log. Heuristic: no primary source was reachable from our record, so the assessment is an automated judgment from secondary sources.

Why are most rows heuristic?

Because honesty beats padding. Most of our catalog records point at articles and list pages, not repositories, so there is nothing primary to verify against yet. We publish those rows as heuristic rather than inventing certainty. The tier table above shows exactly how much of the index is verified on each date.

Is this legal advice?

No. This index is a developer-efficiency reference produced by an automated pipeline with published methodology. It is not legal advice. For high-stakes decisions, consult a lawyer.
