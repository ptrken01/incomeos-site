Quick Start: Run Your Local LLM Server

Here’s how to set up an MLX-based LLM server in 5 minutes:

```bash

Install dependencies

pip install mlx-lm fastapi uvicorn

Serve a model (e.g., Mistral-7B)

mlx-lm serve --model mistralai/Mistral-7B-v0.1 \

--port 8000 \

--host 0.0.0.0 \

--max_tokens 2048 \

--temperature 0.7

```

That’s it. Your server is now listening on `http://localhost:8000`. It handles tokenization, generation, and streaming—all on your M1/M2/M3 Mac.

For developers, this means you can build local AI workflows without hitting rate limits or sending data to external services.

The playbook provides a tested server script that you can customize for your own models:

```python

server.py - minimal deployable server

from fastapi import FastAPI, Request

from mlx_lm import load_model_and_tokenizer

from mlx_lm.utils import generate

app = FastAPI()

model, tokenizer = load_model_and_tokenizer("mistralai/Mistral-7B-v0.1")

@app.post("/generate")

async def generate_text(request: Request):

body = await request.json()

prompt = body.get("prompt", "")

max_tokens = body.get("max_tokens", 2048)

temperature = body.get("temperature", 0.7)

response = generate(

model=model,

tokenizer=tokenizer,

prompt=prompt,

max_tokens=max_tokens,

temperature=temperature

)

return {"text": response}

```

This server is production-ready for local inference with low latency and high throughput.

Performance Metrics

On an M3 Max, serving a 7B parameter model:

  • Startup time: ~12 seconds (including tokenizer load)
  • First token latency: ~0.8 seconds
  • Tokens per second: ~45 tokens/sec (with `max_tokens=2048`)
  • Memory usage: ~12 GB VRAM

You can expect these numbers to scale with model size and hardware, but even a base M1 Mac will handle 3B parameter models with good performance.

FAQ

Q: Can I run multiple models simultaneously?

A: Yes, but memory constraints on Apple Silicon are tight. For 7B models, limit to one server per Mac. Consider running separate processes or using model quantization (4-bit) for more concurrent models.

Q: How does MLX compare to other local LLM solutions?

A: MLX is significantly faster than Python-based alternatives like `transformers` on Apple Silicon due to its optimized kernel support. It's also lighter in resource usage, ideal for local development and deployment.

Q: What about quantization? Does it help with performance?

A: Yes, 4-bit models reduce VRAM usage by ~75% and can increase throughput by up to 2x, especially on M1/M2 chips. The playbook includes quantized model examples for practical deployment.
