48 Prompts That Get Smaller Local Models to Actually Do the Work

Running prompts against a 7B–14B local model is not the same as prompting GPT-4. Small models are literal, forget context fast, and confabulate when a task is ambiguous. The fix is prompt structure, not a bigger GPU. These are the patterns that make local models reliable enough to ship.

Patterns that work on small models

  • One job per prompt. A 7B model told to "summarize and reply and translate" does none of them well. Split into three calls.
  • Show the output shape. Give a one-line example of the exact format you want. Local models match structure better than they follow prose instructions.
  • Constrain, don't hope. "Pick from A, B, C" beats "pick the best option." Fewer degrees of freedom, fewer hallucinations.
  • Recipe, then execute. Ask for a plan first, confirm, then ask it to run the plan. Two passes cut errors sharply.

A minimal template

```

You are <role>. Given <input>, return ONLY valid JSON:

{"decision": "A|B|C", "reason": "<one sentence>"}

Do not explain outside the JSON.

```

That single shape turns a flaky local model into a dependable component.

Multi-pass in practice

For a real task, run two calls: first, "list the three steps to solve this"; second, "execute step 1 only, returning the result." Each call stays small, so the model stays on task. Because MLX on Apple Silicon makes every token free and private, the extra passes cost you nothing but latency.

Few-shot beats zero-shot

When the format is unusual, drop one worked example into the prompt. A single demonstration outperforms a paragraph of instructions on small models — they pattern-match the example far more reliably than they parse a rule.
