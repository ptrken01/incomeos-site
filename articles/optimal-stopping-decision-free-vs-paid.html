When agents face uncertain outcomes, they must decide when to act, sell, or stop — a classic optimal stopping problem. This article provides a practical Python implementation for making such decisions using the Free vs Paid framework.

The Core Problem

Imagine an agent is evaluating offers over time. Each offer has value $v_i$, and there's a cost $c$ to make a decision. The agent wants to maximize expected utility, but must account for uncertainty about future offers.

The optimal stopping rule is: stop when the current offer exceeds the expected value of future offers plus the decision cost.

```python

import numpy as np

def optimal_stopping_decision(offers, cost):

"""

Determine optimal stopping point for a sequence of offers.

Args:

offers: list of offer values [v1, v2, ..., vn]

cost: fixed cost to make decision (c)

Returns:

tuple: (stop_index, stop_value, expected_future_value)

"""

n = len(offers)

if n == 0:

return None, 0, 0

# Calculate expected future values from right to left

expected_future = [0] * n

for i in range(n-2, -1, -1):

expected_future[i] = max(offers[i+1], expected_future[i+1])

# Find optimal stopping point

for i, (offer, future) in enumerate(zip(offers, expected_future)):

if offer >= future + cost:

return i, offer, future

# If no stop point found, accept last offer

return n-1, offers[-1], expected_future[-1]

Example usage

offers = [20, 35, 45, 60, 50, 70, 80]

cost = 10

stop_idx, stop_value, future_val = optimal_stopping_decision(offers, cost)

print(f"Stop at index {stop_idx} with value {stop_value}")

print(f"Expected future value: {future_val}")

print(f"Net gain: {stop_value - future_val - cost}")

```

Key Parameters

  • Offers: Historical or projected values
  • Cost (c): Fixed decision-making cost
  • Expected Future Value: Maximum of remaining offers
  • Stopping Condition: $v_i \geq E[v_{i+1}, ..., v_n] + c$

FAQ

Q: How does this framework handle uncertainty in offer values?

A: This implementation assumes known offers. For uncertain values, add stochastic modeling or Bayesian inference to estimate expected future values, making it a dynamic programming problem.

Q: What's the computational complexity of this approach?

A: O(n) for computing expected future values and O(n) for finding the stop point, giving overall O(n). This scales linearly with offer sequence length, suitable for real-time agent workflows.

Q: Can this be extended to multiple decision points or sequential offers?

A: Yes. Extend by maintaining a state vector tracking current offer, expected value, and time steps. Add recursive calls or use dynamic programming tables for multi-stage decisions, though this increases complexity.
