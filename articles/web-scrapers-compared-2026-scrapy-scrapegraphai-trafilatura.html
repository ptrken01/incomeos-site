Web Scrapers Compared: Scrapy vs ScrapeGraphAI vs trafilatura (Local-First, 2026)

If you need to pull structured data off the web in 2026, three open-source scrapers come up constantly: Scrapy, ScrapeGraphAI, and trafilatura. They are not competitors so much as different tools for different jobs. Here is the honest breakdown — and the local-first setup that actually works.

For the full comparison with a runnable smoke test and license detail, see Web Scrapers Compared on Gumroad.

What each one is for

  • Scrapy — a full crawling *framework*. Use it when you need to follow links, paginate, and orchestrate requests across an entire site. Overkill for one page; ideal for a crawl job.
  • ScrapeGraphAI — an LLM-driven "graph" of scraping steps. Use it when the page structure shifts and you'd rather prompt than maintain XPath. Costs tokens per run.
  • trafilatura — a *readability* library: given a page, it extracts the main text and metadata. Use it when you already have the HTML and just want clean article content.

The decision rule

| You need… | Use |

|-----------|-----|

| Crawl an entire site, follow links | Scrapy |

| Extract main text from a known URL | trafilatura |

| Structure shifts; you'd rather prompt than write XPath | ScrapeGraphAI |

License honesty (the part people skip)

  • Scrapy: BSD-3 — commercial use fine.
  • trafilatura: GPL-3 — fine to use, but watch redistribution terms if you ship it.
  • ScrapeGraphAI: MIT for the library, but it calls external LLM APIs — your token spend, your ToS.
