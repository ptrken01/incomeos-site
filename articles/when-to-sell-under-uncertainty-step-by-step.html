When you're managing assets, investments, or even product launches under uncertainty, deciding *when* to sell is often more important than *what* to sell. Optimal stopping theory provides a framework for making such decisions mathematically.

Consider an agent who observes a sequence of values (e.g., stock prices, bids, or performance metrics) and must decide when to stop observing and sell. The classic example is the "secretary problem" or "37% rule," but in practice, agents often face more complex scenarios with varying reward structures.

Let’s walk through a practical implementation of an optimal stopping agent that can be reused across domains.

Step-by-Step Implementation

We’ll build a simple decision agent that evaluates observed values and decides when to sell based on a threshold. This approach is suitable for cases where you observe values over time and want to maximize expected returns without knowing future values.

Step 1: Setup and Observations

```python

import numpy as np

def optimal_stopping_agent(observations, threshold_type='percentile'):

"""

Decide when to sell based on observed values.

Args:

observations (list): Sequence of observed values.

threshold_type (str): 'percentile' or 'mean'.

Returns:

int: Index where agent decides to stop and sell.

"""

n = len(observations)

if n == 0:

return -1

# Calculate threshold based on type

if threshold_type == 'percentile':

threshold = np.percentile(observations, 75) # 75th percentile

elif threshold_type == 'mean':

threshold = np.mean(observations)

else:

raise ValueError("threshold_type must be 'percentile' or 'mean'")

# Find first value that exceeds threshold

for i, val in enumerate(observations):

if val >= threshold:

return i

return n - 1 # Default to last observation

Example usage:

obs = [100, 120, 90, 150, 130, 180, 160]

decision_point = optimal_stopping_agent(obs)

print(f"Decision point: {decision_point}, Value: {obs[decision_point]}")

```

Step 2: Evaluate and Refine

This simple rule works well in many cases. However, for more sophisticated scenarios (e.g., when you're dealing with noisy data or want to incorporate risk), consider extending the agent:

  • Use dynamic thresholds based on volatility.
  • Add a time penalty if you must act quickly.
  • Incorporate expected value calculations instead of just thresholds.

Example with adaptive threshold:

```python

def adaptive_stopping_agent(observations, window=3):

"""

Uses rolling average to adjust stopping condition.

"""

n = len(observations)

if n < window:

return -1

for i in range(window, n):

avg = np.mean(observations[i-window:i])

if observations[i] > avg:

return i

return n - 1

```

This approach is especially useful when you're observing a series of prices or values that may fluctuate, but you want to act before the trend reverses.

FAQ

Q: How does this apply to investment decisions?

A: In investments, you observe market prices over time and must decide when to sell for maximum return. This agent helps by identifying when a value exceeds historical trends or thresholds, reducing emotional decision-making.

Q: What if I don’t know the future values?

A: The agent makes decisions based on current observations and patterns. It assumes that past behavior may indicate future potential. For high uncertainty, combine with risk-adjusted thresholds.

Q: Can this be extended for multiple assets or sequential decisions?

A: Yes. You can modify the agent to track multiple sequences or apply it iteratively across assets. The core logic remains the same — decide when to stop observing and commit.
